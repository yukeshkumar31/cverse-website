# Increments Manifest — Fix-My-Ride

Each folder is a **runnable checkpoint** after that lesson.  
Trainers can reset a stuck student to the last good increment.

| Path | After lesson | What works |
|------|--------------|------------|
| (Week 1) | Days 1–5 | No code — blueprint only |
| `week-02/day-01-js-rules/` | W2D1 | Pure JS status-transition rules |
| `week-02/day-03-react-shell/` | W2D3 | Vite React app shows title |
| `week-02/day-05-mock-ui/` | W2D5 | Bikes + bookings UI with mock data |
| `week-03/day-03-fastapi-health/` | W3D3 | FastAPI `/health` |
| `week-03/day-05-memory-api/` | W3D5 | In-memory bikes + bookings CRUD + rules |
| `week-04/day-05-schema/` | W4D5 | SQL schema + seed scripts |
| `week-05/day-05-db-api/` | W5D5 | FastAPI + SQLAlchemy + PostgreSQL |
| `week-06/day-05-integrated/` | W6D5 | React calls live API (no auth yet) |
| `week-07/day-05-auth/` | W7D5 | JWT auth + roles |
| `../reference-app/fix-my-ride/` | W8D5 | Final polished BASE |

## How to use

```bash
cd course/increments/week-02/day-05-mock-ui
# follow that folder's README
```

## Rule

Never skip an increment when teaching.  
If behind schedule, finish the current increment cleanly and postpone polish — do not jump to the final app dump.
