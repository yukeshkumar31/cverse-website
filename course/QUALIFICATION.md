# Project Qualification Process

Use this before serious coding begins (Week 1, Days 4–5).

## Purpose

Decide whether the student's idea can become an **8-week base app** — not whether it will succeed commercially.

## Required for approval

1. Real-world problem  
2. Identifiable users  
3. Clear digital solution  
4. At least 3 meaningful entities (or 2 entities + clear transaction)  
5. At least one meaningful relationship  
6. Natural CRUD on at least one important entity  
7. Meaningful business logic (at least one rule)  
8. Search/filtering need  
9. Persistent data need  
10. Frontend ↔ backend communication need  
11. Backend ↔ database communication need  
12. Complete data flow opportunity  
13. Beginner feasible as a **BASE** (after scope cut)

## Decisions

| Result | Meaning |
|--------|---------|
| **APPROVED** | Base scope clear; start Week 2 |
| **APPROVED WITH MODIFICATIONS** | Keep idea; cut features into Enhance Later |
| **REDESIGN REQUIRED** | Problem OK; solution structure needs rewrite |
| **NOT SUITABLE** | Cannot teach Tier 1 base in 8 weeks even after cutting |

## Scope actions

| Action | When |
|--------|------|
| **Keep** | Needed for base features |
| **Modify** | Same goal, simpler version |
| **Remove** | Not needed for learning or problem |
| **Postpone** | Valuable but after course |

## One-level-above rule

The project should stretch the student slightly — not so complex that they only fight scope.

Classify: Too small / Appropriate / Too large / Outside course scope.

## Trainer script

> “We are not rejecting your idea. We are choosing which part you will finish in eight weeks so you leave with a working base — not half of everything.”

## Output of Week 1

Student must have:

1. Problem statement (3–5 sentences)  
2. Users + roles (max 2 for course)  
3. Entity list (mapped to Transfer Sheet)  
4. BASE feature list (checked)  
5. Enhance Later list  
6. Trainer sign-off
