# End-of-Course Assessment Rubric

Evaluate **understanding and a working base**, not feature count or UI beauty.

Score each dimension 0–5. Total /50.

| Dimension | 5 means |
|-----------|---------|
| Problem understanding | Clear real-world problem in their own words |
| Application thinking | Explains users, actions, data, rules, results |
| Frontend | Explains components, state, forms, events |
| Backend | Explains routes, validation, business rules |
| Database | Explains tables, keys, relationships |
| API communication | Explains request/response JSON path |
| Authentication / roles | Explains why login exists; customer vs staff |
| Code ownership | Explains their own code; can make a small change |
| Debugging | Uses a process (UI → network → terminal → DB) |
| Base completeness | All 10 base features work |

## Decision bands

| Score | Result |
|------:|--------|
| 40–50 | Strong base — ready to enhance independently |
| 30–39 | Pass with review notes — patch gaps |
| 20–29 | Incomplete base — extend support days |
| <20 | Restart from last solid increment with mentor |

## Demo checklist (must show live)

- [ ] Register or login  
- [ ] Create owned item (bike / equivalent)  
- [ ] Create transaction (booking / equivalent)  
- [ ] Staff (or admin) changes status legally  
- [ ] Illegal status rejected  
- [ ] Search/filter works  
- [ ] Refresh / restart — data remains  
- [ ] GitHub link + README + Enhance Later  

## What not to over-weight

- Perfect CSS  
- Extra entities beyond base  
- Payment / chat / AI add-ons  
- Memorized definitions without explanation
