# Week 1 — Think Before You Build

**Theme:** From real-world problem → qualified base blueprint  
**Coding this week:** None  
**Reference demo:** Fix-My-Ride (trainer only)  
**Student outcome:** Their own idea, scoped as a BASE app, on a signed Transfer Sheet

---

## Why Week 1 exists

Students often want to open an editor on Day 1.  
If they do that without thinking, they build the wrong thing — or try to build everything.

Week 1 trains **digital thinking**:

```text
Observe a problem
  → Name the people and process
  → Imagine a digital solution
  → Cut scope (BASE now / Enhance Later)
  → Name entities, relationships, actions
  → Qualify + Transfer Sheet
  → Ready for Week 2 UI (still no real backend yet)
```

**Promise to repeat daily:**

> Fix-My-Ride is the *reference*. You build *your* idea.  
> We build the *base* now. Your full vision grows *after* the course.

---

## Week goals

By Friday afternoon, every student can:

1. Explain what an **application** is (SCREEN ≠ APPLICATION; Input → Process → Output).
2. Name **Frontend**, **Backend**, and **Database** in simple words — and why all three matter.
3. Describe a **real-world problem** they care about (not a random tech idea).
4. Propose a **digital solution** that is not too small and not too large for 8 weeks.
5. Separate **BASE** features from **Enhance Later**.
6. Draft **entities**, **relationships**, and **actions** for their idea (mapped from Fix-My-Ride patterns).
7. Complete a **Transfer Sheet** and receive trainer decision:  
   **APPROVED** / **APPROVED WITH MODIFICATIONS** / **REDESIGN REQUIRED** / **NOT SUITABLE**.

## Trainer stance

- Speak in **simple English**; allow Tamil clarification if the cohort needs it.
- Prefer **questions** over lectures.
- Always map Fix-My-Ride words back to **patterns** (Primary user / Owned item / Transaction).
- Never shame a big idea — **postpone** features into Enhance Later.
- Default decision: **APPROVED WITH MODIFICATIONS**, not rejection.
