# Course Overview

## What C-VERSE is teaching

C-VERSE is not a syntax-memorization course.

Students learn the **process of creating a real application**:

```text
Real-world problem
  → Understand people & process
  → Digital solution (scoped)
  → Frontend
  → Backend
  → Database
  → API communication
  → Authentication (basic)
  → Working base app
  → Enhance later
```

## Core principle

> **The student's problem determines the application.  
> C-VERSE determines whether and how that application becomes a suitable learning project.**

- Student owns the idea.
- C-VERSE owns the curriculum and scope.
- Prefer: keep the idea → cut complexity → teach the base → ship → enhance later.

## Base now, enhance later

Eight weeks is enough to build a **working base**, not every feature of every idea.

| In course (BASE) | After course (ENHANCE) |
|------------------|------------------------|
| CRUD on core entities | Extra entities & screens |
| One relationship | Complex workflows |
| One status flow | Notifications, payments, AI |
| One search/filter | Advanced analytics |
| Persist in PostgreSQL | Mobile apps, microservices |
| Simple login + 2 roles | Full org/branch/permissions |

Trainers must say often:

> “This is the base. Your full idea can grow after the course.”

## Teaching model

1. **Problem first** — never introduce tech without a need.
2. **Beginner first** — simple language, analogy, tiny example, then code.
3. **Build while learning** — every practical hour changes the student's app.
4. **Incremental code** — small change → run → verify → next change.
5. **Runnable always** — never leave the project broken between lessons.

## Reference vs student project

| | Fix-My-Ride | Student project |
|--|-------------|-----------------|
| Role | Trainer demo / reference | Personal build |
| Domain | Bike service | Their approved idea |
| Features taught | Same base features | Same base features |
| Words used | Customer, Bike, Booking | Their Transfer Sheet names |

```text

 ↓
BACKEND (FastAPI)
 ↓
BUSINESS LOGIC
 ↓
DATABASE (PostgreSQL)
 ↓
BACKEND RESPONSE

FRONTEND
 ↓

```

## Success definition

The course succeeds when a student can say:

> “I started with an idea, and step by step I built a working base app. I know how the pieces connect, and I can keep improving it.”

Not merely: “We finished 40 topics.”
