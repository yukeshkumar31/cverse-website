# Scope Rules — Protect the Base

## Purpose

Keep every cohort finishing a **working base app** in 8 weeks.

## Always allowed (BASE)

- 2 roles max  
- 3–4 tables  
- CRUD on core entities  
- One status workflow (3 steps)  
- One backend business rule (preferably 2–3)  
- One search/filter  
- Simple JWT auth  
- Clear README + GitHub  

## Never add mid-course (POSTPONE)

- Payment gateways  
- SMS / WhatsApp / email automation  
- AI / ML  
- Real-time GPS / WebSockets  
- Multi-branch organisation complexity  
- Native mobile apps  
- Microservices  
- Docker/CI/CD as required deliverables  

## Trainer script when students ask for more

> “Great idea — write it on Enhance Later. Today we finish the base so you have something that runs. After the course you can add that feature with the same skills.”

## If an idea is too large

1. Keep the **problem** and **users**.  
2. Map to Transfer Sheet patterns.  
3. Move extras to Enhance Later.  
4. Approve as **APPROVED WITH MODIFICATIONS**.  

## If an idea is too small

Add only what naturally belongs:

- A second related entity, or  
- A status field, or  
- A simple rule  

Do **not** invent fake entities just to hit a number.

## Mid-course scope creep checklist

Before saying yes to a new feature, ask:

1. Does it teach a new base skill we still lack?  
2. Can we finish the current Friday milestone without it?  
3. Will it break a beginner’s runnable state?

If any answer is no → Postpone.
