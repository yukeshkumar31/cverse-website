# Trainer Pacing Guide

## Rule

Understanding beats the calendar. If students are lost, slow down.  
If students are ahead, deepen debugging and explanations — do **not** expand scope into Enhance Later features.

## Friday must-ship (minimum)

| Week | Must leave Friday with |
|------|------------------------|
| 1 | Signed Transfer Sheet + BASE/Enhance Later lists |
| 2 | React mock UI: list + create for item + transaction |
| 3 | FastAPI memory API: CRUD + one business rule |
| 4 | PostgreSQL tables created; student can run a JOIN |
| 5 | API reads/writes PostgreSQL |
| 6 | React talks to live API for core flows |
| 7 | Login works; customer vs staff difference visible |
| 8 | GitHub repo + demo + Enhance Later backlog |

## If you are behind

| Situation | Cut this first | Never cut |
|-----------|----------------|-----------|
| Slow on React | Fancy CSS, extra pages | Forms + list + state |
| Slow on FastAPI | Extra endpoints | One entity CRUD + one rule |
| Slow on SQL | GROUP BY, indexes deep dive | PK/FK + SELECT/INSERT + one JOIN |
| Slow on auth | Refresh tokens, OAuth | Register/login + protect one route |
| Slow overall | Week 8 polish | Full data flow once |

## Daily rhythm

1. Continuity (2–3 min): what we had yesterday  
2. Problem (5 min): why today's concept exists  
3. Theory + live demo on Fix-My-Ride  
4. Students mirror on their Transfer Sheet names  
5. Run + verify  
6. Checkpoint questions  
7. Git commit if code day: “Save this working point”

## Student project vs reference

- Trainer projects Fix-My-Ride on screen.
- Students rename entities; same steps.
- Do not let a student rebuild a different architecture mid-course.
